# AI Project Setup

Набор правил, шаблонов и рабочих процессов, которые позволяют AI-агентам работать в репозитории структурированно и предсказуемо.

Проект не предоставляет CLI, установщик или runtime-код. Его продукт — договорённость: как агент ведёт себя в проекте, как документируется архитектура и как передаётся контекст между сессиями.

## Текущая цель

Создать минимальную, но рабочую основу для AI-агентного разработчика:

- `AGENTS.md` задаёт постоянные правила поведения агента в проекте.
- Шаблоны документации в `docs/` определяют, что и как нужно фиксировать.
- Рабочий процесс документирования (`docs/workflows/documentation-maintainer.md`) описывает, когда и как обновлять документацию после завершения задачи.

## Структура репозитория

```
ai-project-setup/
├── AGENTS.md                                  # Постоянные правила агента
├── README.md                                  # Этот файл
└── docs/
    ├── ARCHITECTURE.md                        # Текущая архитектура проекта
    ├── DECISIONS.md                           # Реестр важных решений
    ├── HANDOFF.md                             # Состояние для передачи между сессиями
    └── workflows/
        └── documentation-maintainer.md        # Процесс обслуживания документации
```

## `AGENTS.md`

Файл с постоянными правилами для AI-агентов, работающих в репозитории. Он определяет:

- что нужно сделать перед началом задачи;
- каковы правила реализации;
- как определяется завершённость задачи;
- как обслуживается документация;
- как работает HANDOFF;
- какая документация является источником истины.

Агент не должен менять код, не понимая контекста. `AGENTS.md` — договорённость, а не описание функциональности.

## Шаблоны документации

Файлы в `docs/` на текущем этапе представляют собой заготовки с заданной структурой разделов. Содержимое появится по мере развития проекта.

- **`docs/ARCHITECTURE.md`** — описывает, как устроена система (компоненты, потоки, ограничения).
- **`docs/DECISIONS.md`** — фиксирует принятые технические решения с обоснованием.
- **`docs/HANDOFF.md`** — хранит текущее состояние проекта, важное для корректного продолжения работы другим агентом или сессией.

Шаблоны не являются плейсхолдерами, которые нужно заполнить немедленно. Они становятся актуальны, когда проект обрастает архитектурой и принятыми решениями.

## `docs/workflows/documentation-maintainer.md`

Рабочий процесс, определяющий:

- когда нужно обновлять документацию после завершения задачи;
- какие файлы затронуты;
- как проверять актуальность `HANDOFF.md`;
- как записывать решения в `DECISIONS.md`;
- как обновлять `ARCHITECTURE.md`.

Процесс не запускается автоматически после каждого коммита. Он применяется, когда задача реально изменила состояние проекта.

## Scope MVP

На текущем этапе в scope входит:

- `AGENTS.md` с полным набором базовых правил;
- шаблоны `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`, `docs/HANDOFF.md`;
- рабочий процесс `docs/workflows/documentation-maintainer.md`;
- этот `README.md`.

Не входит в scope MVP:

- установщик (installer);
- CLI-интерфейс;
- vendor-specific файлы (`CLAUDE.md`, `GEMINI.md` и аналоги);
- skills и adapters;
- runtime-код.
